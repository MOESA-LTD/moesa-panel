# M20 Layer 3 — Terms Registry, Inline Markers and the System Guide: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every process code, rule, abbreviation, package, gate, incident family and severity that the panel's copy uses gets one explanation: a dotted, clickable `<abbr>` wherever guide, glossary, hint copy or a form label names it, and a role-agnostic "System guide" page that lists them all.

**Architecture:**
- **Registry.** `TERMS` (`app/src/constants/terms.ts`) maps each code to its category, its i18n slug and (optionally) a Drive link. Package, gate, family and severity entries are generated from the layer 1 enums (`PACKAGES`, `GATE_CODES`, `INCIDENT_FAMILIES`, `INCIDENT_SEVERITIES`), so their short line is the existing glossary line; process documents, rules, abbreviations and the `(M)` mark are listed by hand. Copy lives in i18n: `terms.<slug>.short` (hand-listed terms only) and `terms.<slug>.long` (every term).
- **Markers.** Copy stays a plain string; a code is written `[[S09]]`. `TermText` splits a string into text and `Term` atoms; a `Term` is an `<abbr>` with the short line as a PrimeVue tooltip, and a click opens the page guide panel's terms section on that code (`useGuideStore().showTerm`), or, on the system guide page, jumps to the code's entry. Plain-text surfaces (tooltips, `title`, `aria-label`, toasts) never receive markers: they read `stripTerms(...)`, and an i18n test confines markers to guide, glossary, term, system guide and three hint keys.
- **Forms.** `FormField` gains `term?: string`; the label is rendered through `TermText(markLabel(label, term))`, so label strings stay unmarked.
- **System guide.** Route `guide` under the dashboard layout, hidden from the sidebar, opened from the guide panel's footer and the account menu. It is generated from `TERMS` by section, after a hand-written "How the panel works" section.

**Tech Stack:** Vue 3.5 + PrimeVue 4 + Tailwind, pinia, vue-i18n 10, vue-router 4, vitest 3 (happy-dom).

**Spec:** `docs/superpowers/specs/2026-11-03-moesa-panel-modules-design.md` §6 M20, paragraph "Katman 3 — terimler ve sistem rehberi" (read the whole M20 section), and K7 (language). Existing guide code and conventions: `docs/superpowers/plans/2026-11-04-phase2c-matrix-incidents-guides.md` Tasks 11–13. Content sources (repo-external, `A:\job\e-commerce\moesa\ABOUT MOESA`): `03_SABLONLAR/S05…S17`, `02_YONERGELER/Y10` §1, §4, `01_IS_AKISI/moesa_is_akisi.md` (gates), `05_RAPORLAR/05_sektor_sozlugu.md` (abbreviations), `00_BENI_OKU.md` §3–§4; the K rules from the spec §4.

## Global Constraints

- i18n: `en` is the source, `tr` is hand-written, the other locales come from `pnpm i18n-sync` (run without flags; the script has no check mode; it adds missing keys with the English text and never overwrites a value, so the other locales keep their old, unmarked guide copy; that is accepted). No user-visible literal in a component.
- K7: "Süreç kodları (P1, G2, PL-G3) her dilde aynı kalır." A marker's code is identical in `en` and `tr`; a string that marks codes marks the same multiset of codes in both.
- Copy is plain text: no Markdown, no HTML. vue-i18n syntax characters `{`, `}`, `@`, `|`, `$` never appear in copy except the named parameters given here (`{code}`).
- **Marker grammar:** `[[CODE]]`, `CODE` a key of `TERMS` (`[[(M)]]` for the (M) mark). Mark the first occurrence of a code in a string only; a code inside a longer code is not a code (`PL-G4` is not `G4`; `OL-09` is written `[[OL]]-09`); suffixes stay outside (`[[PI]]'ı`, `[[SKU]]s`).
- **Where markers may appear:** keys under `guide.pages.`, `glossary.`, `terms.`, `system_guide.`, and exactly `ops.incident.preventive_hint`, `ops.change_request.customer_approval_hint`, `ops.product.import.hint`. Never in `errors.*`, labels (`fields.*`, `ops.*.fields.*`, `route.*`), `guide.panel.*` or any `terms.<slug>.short` (a short line is a tooltip and stays plain).
- **Copy tables.** EN/TR copy is given as `EN / TR`. The developer drafted it from `ABOUT MOESA`; the spec makes TR the owner's to review, so the whole TR column of Tasks 1 and 4 and every TR string changed in Tasks 3, 6 and 7 go to the owner in the final summary **[owner to confirm]**. The marker never goes into the JSON. EN is the developer's.
- Components under `app/src/components/` are auto-registered (unplugin-vue-components, `components.d.ts` is regenerated by `pnpm typecheck`/`build`; commit it). `v-tooltip` is the PrimeVue `Tooltip` directive.
- View tests import `tests/setup/mockMain.ts` first. Component tests mount with `i18NPlugin`, `PrimeVue` and, where the store is read, a fresh pinia, as `tests/components/PageGuide.test.ts` does. happy-dom has no reliable `scrollIntoView`: tests assign `Element.prototype.scrollIntoView = vi.fn()`; code calls `el?.scrollIntoView?.(…)`.
- Commands run in `app/`. Each task ends green on `pnpm test && pnpm typecheck && pnpm lint`.
- Commits are conventional. Each commit step names the paths to `git add` and the subject; the message ends with a blank line and the Co-Authored-By trailer your session provides (never a placeholder, never a hard-coded model name).

## Review Focus

1. **Raw `[[…]]` leaking into plain text** — a tooltip, `aria-label`, `title`, toast or a select option showing `[[PSI]]` after a glossary line is marked. Expected: every plain consumer shows `PSI`. Tests: Task 1 "marks codes only in guide, glossary, term and hint copy"; Task 7 SelectEnum, StatusActions, GatePanel and PhaseStrip cases on marked lines.
2. **A term click doing its parent's job** — clicking a term inside a `<label>` focuses the input, inside an accordion header toggles the task, inside a row opens the record. Expected: the click only opens the term. Tests: Task 2 "stops the click at the term"; accordion titles render `static` terms (Task 5 "renders the guide copy with its terms").
3. **EN/TR drift** — a translator marks `[[PI]]` in EN but not in TR, or types an unknown code (`[[S9]]`). Expected: the test suite fails, and at runtime the unknown code shows as plain text. Tests: Task 1 parity and unknown-token cases; Task 2 "leaves an unknown code as text".
4. **A term clicked where the page has no guide** (account pages, the system guide itself, a card opened from another page) or **after navigating with the panel closed**. Expected: the panel opens on the term of the current route (or the term alone), never on a stale page; on the system guide page the click jumps to the entry. Tests: Task 2 store cases; Task 4 "moves to a term clicked on the page"; Task 5 "shows a term on a route without a guide".
5. **A link with a code in its address** — opening `/guide#term-L_G1` from the panel footer or a bookmark. Expected: the page scrolls to the L-G1 entry. Tests: Task 4 "opens a term from the address"; Task 5 "links to the system guide on the focused term".

**Interfaces:**
- Consumes: `GLOSSARY_ENUMS`, `glossaryKey`, `type GlossaryEnum` (`@/api/glossary`); `PACKAGES` (`@/api/customer`), `GATE_CODES` (`@/api/project`), `INCIDENT_FAMILIES`, `INCIDENT_SEVERITIES` (`@/api/incident`) — read through `GLOSSARY_ENUMS.package`, `.gate_code`, `.incident_family`, `.incident_severity`.
- Produces (`app/src/constants/terms.ts`):
  - `TERM_CATEGORIES = ['process', 'rule', 'package', 'gate', 'family', 'severity', 'abbreviation'] as const`; `type TermCategory`.
  - `type Term = { code: string; category: TermCategory; slug: string; glossary?: { enum: GlossaryEnum; value: string }; drive?: string }`.
  - `TERMS: Readonly<Record<string, Term>>`, insertion order = `TERM_CATEGORIES` order, then the order below. `TERM_CODES: readonly string[]` (= `Object.keys(TERMS)`).
    - process: `S05 S07 S08 S09 S10 S11 S12 S13 S14 S15 S16 S17 Y10`; rule: `K5 K6 K7 K8`; abbreviation: `PI PSI ETD ETA CMR GTIN EAN ASIN SKU`. Slug = code.
    - package: one per `PACKAGES` value (`A0 A1 A2 B C D E`), code = slug = value, `glossary: { enum: 'package', value }`.
    - gate: one per `GATE_CODES` value, code = `value.replaceAll('_', '-')` (`G1`…`G5`, `PL-G1`…`PL-G4`, `L-G1`, `L-G2`), slug = value, `glossary: { enum: 'gate_code', value }`; then `(M)` with slug `M_gate` and no glossary.
    - family: one per `INCIDENT_FAMILIES` value, code = slug = `value.toUpperCase()` (`OL OA OU OT OM`), `glossary: { enum: 'incident_family', value }`; severity likewise from `INCIDENT_SEVERITIES` (`S1 S2 S3`, enum `incident_severity`).
    - `drive`: from `const DRIVE_LINKS: Partial<Record<string, string>> = {}`, which ships empty (owner ruling: no Drive links until the owner gives the documents' URLs); a link is copied onto its term only when `driveLinkValid(url)`.
  - `driveLinkValid(url: string): boolean` — true only for `https://drive.google.com/…` and `https://docs.google.com/…`.
  - `isTermCode(code: string): boolean`; `termSlug(code: string): string`; `termKeys(code: string): { short: string; long: string }` — short is `glossaryKey(enum, value)` for a term with `glossary`, else `terms.<slug>.short`; long is always `terms.<slug>.long`.
  - `termsOf(category: TermCategory): string[]`; `termOfGlossary(e: GlossaryEnum, value: string): string | undefined` (the code whose `glossary` is that pair).
  - `type TermPart = { text: string } | { code: string }`; `parseTerms(text: string): TermPart[]` (an unknown code becomes `{ text: code }`); `stripTerms(text: string): string`; `markLabel(label: string, code: string): string` (wraps the first occurrence of `code` bounded by `(?<![A-Za-z0-9])…(?![A-Za-z0-9])`, regex-escaped; without one, appends `' [[code]]'`).
  - Task 2 adds `TERM_SELECT` and Task 4 adds `TERM_SECTIONS`, `SYSTEM_GUIDE_TOPICS` to this file.

- **GTIN**: Global Trade Item Number: the barcode number that identifies a product worldwide. / Global Trade Item Number: ürünü dünya genelinde tanımlayan barkod numarası. — It is the general name of [[EAN]], UPC and similar codes: 8, 12, 13 or 14 digits with a check digit, bought from GS1. İki farklı pakette aynı EAN listing'leri birleştiren bir hatadır ([[OA]]-05). Panelde ürünün [[GTIN]]'i olarak girilir.
- **ASIN**: Amazon Standard Identification Number: the 10-character ID of a product page on Amazon. / Amazon Standard Identification Number: Amazon'daki ürün sayfasının 10 karakterlik kimliği. — Amazon gives it when the listing is opened; several sellers can sell under one ASIN. - **SKU**: Stock keeping unit: the seller's own code for one product variant. / Stok kodu: satıcının bir ürün varyantı için kendi kodu. — One variant is one SKU and one row of the product master ([[S10]]); it holds no platform or country. A SKU is unique. / Bir varyant bir SKU ve ürün ana tablosunda bir satırdır ([[S10]]); platform ya da ülke içermez. Pazar yerinde aynı ürünün kendi platform SKU'su olabilir; pazar hücresinde tutulur.
